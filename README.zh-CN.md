# Trace · Qlik 血缘与迁移工作台

面向数据开发、治理和迁移分析人员的本机工具，支持从 Qlik Sense 导出元数据中分析字段血缘、表级血缘、代码证据和 QuickSight 迁移复杂度。

**公开版不附带任何 Qlik 元数据、内部报告或业务截图。** 原有三栏结构、多 Stream、字段搜索、上下游高亮、代码查看和迁移评估功能保留。项目不需要 Qlik、数据库或 AWS 账号，也不会直接创建 QuickSight 资源。

## 启动与导入

Windows 便携版：从 GitHub Releases 下载公开版 Windows x64 ZIP（发布后可用），完整解压后双击 `Start-Trace.cmd`，保持命令窗口打开。默认端口为 8775，占用时依次尝试后续 30 个端口，以启动窗口显示的地址为准。便携版已包含运行时，无需安装 Python 或 Node.js。

初次打开时显示导入引导：点击「选择元数据目录」→ 输入本机导出根目录的完整路径 →「扫描并导入」→ 在左侧选择 Stream、App，再选择 Sheet 和字段。

从源码运行需要 Python 3.10+、Node.js 20+（推荐 24 LTS）：

```powershell
.\Setup.ps1
.\Start-Local.ps1
```

默认空目录是项目下的 `metadata/apps`。可以把自己的导出放进去，也可以使用任意本机外部目录。外部目录通过界面选择后，仅在本次服务进程内有效；重启时要重新导入，或明确指定启动参数：

```powershell
# 源码版
.\Start-Local.ps1 -MetadataRoot 'D:\QlikExports\apps' -Port 8875
# 便携版
.\Start-Trace.cmd -MetadataRoot 'D:\QlikExports\apps' -Port 8875
```

## 更换为生产环境元数据

1. 将获准使用的生产导出保存到本机单独目录，保留 `Stream/App` 分组及各 App 原有文件结构。可使用新的日期目录保存不同快照。
2. 在「元数据目录」中输入生产导出的根目录，点击「扫描并导入」。导入仅读取文件，不修改源文件，也不连接生产 Qlik 或数据库。
3. 核对 Stream 数量、各 Stream 的 App 数量以及导入失败提示，检查代表字段是否能到达预期源表，并逐层查看代码。
4. 导入成功后，工作台切换到新的分析快照；导入空目录或全部失败时保留原快照。部分 App 失败时会导入其余 App 并显示错误，需要补齐文件后再次扫描。
5. 回到测试数据时，以相同方式导入测试根目录。刷新浏览器不等于重新扫描磁盘；导出有更新后需要再次导入。

更详细的目录格式、必需文件、Stream 优先级与排错方法见[元数据导入说明](./docs/metadata-import.md)。`.qvf` 文件本身不能直接解析。

## 分析与分享边界

血缘依据已导出的脚本与对象进行静态分析。外部 Include、动态语句、数据库视图内部逻辑、通配符 schema 或复杂选择上下文可能需要人工核实；迁移工时须通过试迁移校准。

服务仅监听本机回环地址，无多用户认证。运行期间不需要网络；首次源码安装需要访问依赖仓库。分析结果、源代码证据和截图可能包含业务信息，请保存在本机，不要提交到公共仓库或公开 Issue。

测试与打包步骤见[发布说明](./docs/releasing.md)，许可和依赖归属见[第三方说明](./THIRD_PARTY_NOTICES.md)。
